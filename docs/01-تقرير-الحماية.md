# Dr. Huda Dental V2 · المرحلة 1: فحص الحماية

تاريخ الفحص: 13 تشرين الثاني 2026 · النسخة المنشورة لم تُمس.

## ما هو سليم حالياً
- لا يدخل أي شخص إلا بحساب مؤكد البريد، ومضاف من الإدارة (مجموعة members) أو من المالكين.
- الزائر من الموقع لا يقرأ أي بيانات، ويرسل طلب حجز فقط بحقول محددة وحجم محدود.
- لا توجد كلمات مرور أو أسرار داخل ملفات الواجهة. مفتاح Firebase Web API عام بطبيعته ولا يعطي صلاحية بدون القواعد.
- لا يوجد بيانات مرضى في مستودع GitHub.

## الحل: قواعد الإصدار 2 (مرحلة أ)
الملف: `security/firestore.rules.v2`. متوافق مع النظام الحالي بدون تغيير أي بيانات أو أسماء مجموعات.
- يسد الثغرات 1 و2 و3 و5 بالكامل.
- الثغرة 4: القراءة تبقى لكل الأعضاء بهذه المرحلة، لأن النظام الحالي يحمّل المجموعات كاملة. تُعزل بالمرحلة ب مع تحديث طريقة التحميل في V2.
- اختُبرت على محاكي Firestore: **86 اختبار، كلها ناجحة** (`security/rules-tests.mjs`).

## أثرها على العمل اليومي (تغييرات تحتاج موافقتك)
- **الموظف** (حتى «كاملة داخل عيادتها») لم يعد يستطيع: تعديل بيانات العيادة، دفع الإيجار، إقفال/فتح الأشهر، صرف الرواتب، تعديل الإعدادات، حذف مريض. هذه تبقى للمالك و«المدير العام».
- **الموظف** يحذف فقط السجلات التي أنشأها هو (علاج، مصروف، موعد…).
- **الطبيب** لا يستطيع تعديل نسبته أو بياناته.
- ربط الحساب برمز الدعوة يبقى يعمل، لكن كل شخص يربط سجله هو فقط.

## طريقة التطبيق (بعد موافقتك فقط)
1. خذ نسخة احتياطية (راجع ملف 02).
2. افتح Firebase ← Firestore ← Rules، احفظ القواعد الحالية في ملاحظة (للرجوع).
3. الصق محتوى `firestore.rules.v2` واضغط Publish.
4. جرّب الدخول بحساب سكرتيرة وحساب مدير.
5. للرجوع: الصق القواعد القديمة واضغط Publish (يأخذ أقل من دقيقة).
